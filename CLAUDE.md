# panorama-season-2-auction/ (Season 2 auction)

The Season 2 auction as a self-contained public release: `frontend/` (Next.js 16 App Router app built with vinext on Vite, served as a Cloudflare Worker; React 19, TypeScript, Tailwind CSS 4, pnpm) plus an auction-only `contracts/` Foundry project (PanoramaSeason2Auction + Panorama + mint controller, tests, lifecycle scripts, runbook, ops tooling). The frontend is the **standalone Season 2 auction site**, split out of `frontend/` so auction traffic deploys/scales independently. Serves `/` (bidding; the old `/auction` path 307-redirects here), `/admin` (wallet-gated owner console, noindexed), and `/recovery` (public self-serve settlement/refund tools, linked from the FAQ). Copies the minimal shared infra it needs (wagmi config, wallet modal/pill, toast, theme provider, `constants`, `useAddressLabel`, `panoramaAuction` ABI); uses Hanken Grotesk as its clean base font instead of the site's display serif. Vitest units + Playwright/anvil E2E under `test/unit/` and `e2e/` (`e2e/setup-chain.mjs` auto-detects the sibling Foundry project, so the app runs unchanged in this repo or extracted standalone). This is the ONLY home of the auction contract/tests/scripts/runbook/ops tooling; `smart-contracts/` no longer carries any auction code (its internal pre-audit report `AUCTION_AUDIT_REPORT.md` remains there as a historical record; the public audit is `panorama-season-2-auction/Audit.pdf`).

## The contract

- **PanoramaSeason2Auction** (`panorama-season-2-auction/contracts/src/PanoramaSeason2Auction.sol`) — Multi-unit English (open ascending) auction with uniform clearing price, used to sell Season 2 tokens #91-#180 (90 units). Solady `Ownable` + `ReentrancyGuardTransient`. Bidders bid the max they'd pay; the top 90 bids win and all pay the 90th-highest (the clearing price), excess refunded at settlement. The reserve is contract-floored at **`MIN_RESERVE_PRICE` = 0.1 ETH** (constructor rejects lower configs, `placeBid` rejects anything below the reserve, so no bid under 0.1 ETH is ever accepted). Only the top 90 bids escrow funds: once full, a new bid must beat the current lowest winning bid by `minIncrementBps` (**ceiling** bps math, so the advertised percentage is never rounded down) and the displaced bidder is refunded immediately (`SafeTransferLib.forceSafeTransferETH` so a griefer can't block bidding). The active set lives in a custom 1-based indexed binary **min-heap** (`_heap` + `heapPos` bijection); the root is the clearing floor; equal amounts tie-break to the earlier bid id (earlier reveal slot; the latest equal bid is displaced first). Each wallet holds up to 4 independent bids (`increaseBid` tops one up; `siftDown` on increase) and can win up to 4 tokens. Anti-snipe: any qualifying bid in the last 5 min sets `endTime = now + 10min`, capped by immutable **`absoluteEndTime` = scheduled end + `MAX_TOTAL_EXTENSION` (24h)**. A new `placeBid` always qualifies; an `increaseBid` extends only when the top-up is ≥ `minIncrementBps` of the current clearing floor (`minIncreaseForExtension()`), and **inside the window a sub-threshold increase reverts** (`BidIncreaseTooLow`) so a competitive raise cannot be split to dodge the rule. Bidding fails closed if `nft.totalMinted() != 90`. Phase machine `Active → Finalizing → Settled` vs `→ Cancelled` (mutually exclusive). `finalize(maxCount)` (owner, or anyone after `endTime + FINALIZE_GRACE` = 7 days) settles in batches: freezes the clearing price and winner count once, re-checks supply/authorization/cap **every batch**, requires each minted id to equal `91 + finalizeCursor` (reverts `UnexpectedSupply`/`UnexpectedTokenId` atomically otherwise), mints winners **highest-bid-first** (top bid → #91 → earliest daily reveal slot; O(winners) per mint), refunds excess (`trySafeTransferETH` + `pendingReturns` pull-ledger fallback), and on the last batch splits proceeds 58%/42% to `payoutA`/`payoutB`. Failsafes: owner `cancelAuction()` (Active-only) then **permissionless** `refundAll(maxCount)`; **permissionless `recoverFromSupplyMismatch(maxCount)`** the moment an external mint consumes an expected token id (no waiting period); **permissionless `emergencyRefund(maxCount)`** after `absoluteEndTime + EMERGENCY_GRACE` (30 days) — refunds every still-unminted bid, releases already-minted winners' proceeds, never touches the NFT. All recovery paths share one idempotent completion; `refundsComplete` may need one final call after the last live bid refunds, so UIs gate on the flag, never on the bid count. `withdraw()` pulls ledgered refunds. Owner extras: `setSchedule` (until first bid), `setPaused` (gates bids only; the clock keeps running), liability-aware `rescueSurplusETH` (terminal states only; escrow untouchable) plus `rescueERC20`/`rescueERC721`. `finalize(45)` ≈ 8.1M gas; batch 30-45 (hostile refund receivers can add ~100k gas per winner). Needs `setAuthorizedOperator(auction,true)` + a Season 2 mint cap + `totalMinted==90` to mint. **Settlement: `script/SettleAuctionAtomic.s.sol`** (in `panorama-season-2-auction/contracts/`) runs authorize → exact-winners cap → finalize batches → revoke as one closed sequence (EOA `run()`, or `--sig 'safeBatch()'` printing Safe Transaction Builder JSON for a single atomic Safe transaction). It is the ONLY settle path — the legacy split scripts (AuthorizeAuction then FinalizeAuction) were removed because the gap between the steps is exactly the privileged mint window the atomic sequence closes; contingency is the `/admin` console (or `/recovery` after the 7-day grace) driving the contract's `finalize` directly. Other scripts: `DeployAuction` / `DeployAuctionSepolia` / `SettleAuctionAtomicSepolia` / `CancelAuction` / `RefundAllAuction`. All auction scripts are mainnet-gated (`_requiredChainId()` is virtual on `DeployAuction` and `SettleAuctionAtomic`; `DeployAuctionSepolia.s.sol` / `SettleAuctionAtomicSepolia.s.sol` override it to 11155111 for testnet rehearsals with identical validation), validate full-width env before narrowing, pin `PANORAMA_AUCTION_RUNTIME_CODEHASH`, and **require an explicit `PRIVATE_KEY`** (`Base.s.sol` has no fallback key). Ops (all under `panorama-season-2-auction/contracts/`): `AUCTION_RUNBOOK.md` (checklists, incident playbooks, fork rehearsal; settle within 7 days of the final `endTime` is a HARD deadline — past it, `recoverFromMintingUnavailable` lets anyone cancel a successful sale, audit C-M1), `scripts/auction-manifest.sh` (deployment manifest JSON), `scripts/monitor-auction.sh` (cron monitor with Discord alerts).

## Patterns

- **Season 2 auction (custom on-chain)**: `PanoramaSeason2Auction.sol` sells Season 2 (#91-#180) via a multi-unit English auction with uniform clearing price (see the contract description under Smart Contracts). Independent of the SuperRare/daily flow above. Frontend lives in the **standalone app at `panorama-season-2-auction/frontend/`** (not `frontend/`), three routes: the public bidding page `/auction`, the **wallet-gated** owner console `/admin` (verifies connected wallet `== owner()`; finalize batches clamped to ≤60, cancel, refundAll gated on `refundsComplete` not bid count, pause; `noindex` via layout metadata + `X-Robots-Tag`), and the public **`/recovery`** page (linked from the FAQ security item: withdraw, permissionless finalize after the 7-day grace, cancelled refunds, supply-mismatch recovery, emergency refund — each with live availability, countdown to eligibility, and an Etherscan `#writeContract` fallback). Bidding page layout: two independently-scrolling panes (`lg:h-dvh`), collapsible bidding rail LEFT on desktop and FIRST on mobile (bid form above the intro article) with a desktop maximize toggle (`railMax`: rail goes full-width, content centered at a readable max width, details pane hidden; collapsing always exits it; persisted in localStorage and applied BEFORE first paint via `lib/railMax.ts`'s inline script stamping `html[data-rail-max]` + CSS in `globals.css`, so reloads never jump layouts, while the collapsed strip deliberately does not persist; React state only mirrors the attribute for labels). NOTE: `layout.tsx` is a server component, so pre-paint inline scripts must come from server-safe modules (`lib/themeScript.ts`, `lib/railMax.ts`), never from a `"use client"` module (that serializes a client-reference stub, silently breaking the script), `AuctionIntro` (how-it-works + 12-question FAQ incl. the 24h-extension-cap rule, the trustlessness item, and the audit question; footer + FAQ link the published audit via `AUDIT_REPORT_URL`) on the right; the hero is `HeroPanorama`, a drag-to-pan strip of static Season 2 CDN images (no CDN metadata reaches any URL builder). **Number handling**: `src/lib/format.ts` is the only formatter — `ethExact` (exact `formatEther`, what quick-fills put in inputs), `eth`/`ethCeil` (display only; ceil for minimums so "type what you see" never reverts), `normalizeDecimalInput`/`parseEthInput` (comma→dot; a comma can never silently change magnitude); no `toLocaleString` anywhere. **State** (`useAuctionState`): one unified `panoramaAuctionAbi` (functions + events + all 30 custom errors), `useReadContracts` with `allowFailure: false` (fail closed — no zero-defaults; `readFailed` renders an error surface, `degraded` disables actions on stale data), `useBlock({watch})` drives a chain-anchored clock (`useChainNow`: block timestamp + elapsed; device clock never decides live/ended) + per-block refetch, 3s polling inside the last 15 min, `displayPhase` (`src/lib/phase.ts`, unit-tested) splits the contract's `active` span into `upcoming`/`active`/`closed` for the status label + `LiveDot` on all three routes (raw phase is `active` from deploy until finalize, so it would read "Live" during the pre-start countdown), and `wonBids` reconstructed from `Won` event logs (`NEXT_PUBLIC_AUCTION_DEPLOY_BLOCK` bounds the scan) so `Standings` persist through and after settlement (minted rows tagged, ranks = tokenId-90). ALL THREE routes (bidding, /admin, /recovery) lock writes the moment reads are degraded or stale (`writeBlocked = busy || degraded || stale`); the alarming data-health banner is separately debounced via `degradedPersistent` (~30s of persisting trouble, i.e. a couple of failed polls) so a single self-healing hiccup never flashes it. Pending-tx records are per wallet (`localStorage` key suffixed with the account; hydrate rejects records from a different account), so wallet B is never locked by, or toasted for, wallet A's unresolved transaction. DemoBar renders on all three routes whenever demo is active. **Actions** (`useAuctionActions`): every write is `simulateContract`-ed first so doomed txs surface a decoded custom error before the wallet opens; `describeAuctionError` (`src/lib/auctionErrors.ts`) maps reverts to one sentence and returns null for user rejections; success/error/info toasts (aria-live), displacement detected by yourBids-shrink diff ("You were outbid"), last tx link survives confirmation. Demo mode (`?demo=1`, `demoStore.ts`) mirrors Solidity exactly: ceil bps, extension cap + in-window sub-threshold raise rejection, straight-to-wallet refunds, id tie-breaks, winnerCount/finalizeCursor, time-gated emergencyRefund; the `?demo=1` URL param is ignored on mainnet production builds (`useIsDemo` gates it on `NODE_ENV !== "production" || chainId !== 1`), so live-site demo requires the `NEXT_PUBLIC_AUCTION_DEMO=1` build flag. **Config**: `src/lib/env.ts` validates NEXT_PUBLIC_* at build time via `next.config.ts` (production builds, `PANORAMA_PRODUCTION=1` or `VERCEL_ENV=production`, REJECT `NEXT_PUBLIC_AUCTION_DEMO` outright, and mainnet ones additionally REQUIRE `NEXT_PUBLIC_RPC_URL` + WalletConnect id + deploy block, and cross-check CDN/GitHub URL overrides); `NEXT_PUBLIC_BLOCK_EXPLORER_URL` must match the chain's canonical Etherscan on 1/11155111 and defaults per chain; the app's own origin is `AUCTION_SITE_URL` = `https://season2.panorama.garden` (WalletConnect metadata + OG canonical; `SITE_URL` stays the main site for outbound links); CSP + security headers in `next.config.ts`; WalletConnect connector only registers when an id exists; chain 31337 (anvil) supported for E2E. **Tests**: `pnpm test` = vitest units (format round-trips, error decoding, demo parity); `pnpm test:e2e` = Playwright + anvil (`e2e/` boots anvil 8546, deploys Panorama+controller+auction from forge artifacts, injects an EIP-6963 wallet shim over anvil's unlocked accounts; covers bidding, front-run revert recovery, displacement notice, anti-snipe extension, wallet rejection, tx replacement, batched admin settlement with post-settlement board + `ownerOf` order, cancel+batched refunds, permissionless finalize via /recovery, demo smoke, mobile rail-first + bid) with snapshot/revert isolation; CI in `.github/workflows/ci.yml` (lint+typecheck+unit+vinext build+prod audit, forge tests, e2e). Contract tests in `panorama-season-2-auction/contracts/test/PanoramaSeason2Auction*.t.sol` (113 tests: unit + fuzz + invariants — heap property, `heapPos` bijection, exact solvency through settlement, no-overmint, per-wallet cap; handler drives finalize/emergency/cancel/competing-mint; plus atomic-settlement script tests). Scripts in `panorama-season-2-auction/contracts/script/{DeployAuction,DeployAuctionSepolia,SettleAuctionAtomic,SettleAuctionAtomicSepolia,CancelAuction,RefundAllAuction}.s.sol`; ops in `AUCTION_RUNBOOK.md` + `scripts/{auction-manifest,monitor-auction}.sh`. Formally audited July 2026 (public report: `panorama-season-2-auction/Audit.pdf`); all frontend High/Medium findings are fixed in-tree, and the one contract note (C-M1) is operational: settle within 7 days of the final `endTime`.
- **Auction stats tool (`panorama-season-2-auction/stats/`)**: Standalone Node/TS project (own `package.json`, viem + resvg + opentype, `pnpm stats`) that reads the deployed auction and writes `output/`: `auction-stats.txt` (full sheet), `bidders.txt` + `bidders-plain.txt` + `bidders-addresses.txt` (every unique bidder wallet, ENS-resolved, for thank-yous), `standings.txt` (ranked board with the token id each rank receives), `auction-stats.json`, and `auction-infographic.png` (3200px poster, site dark palette, Hanken Grotesk + JetBrains Mono vendored as TTFs in `fonts/`). Works both while bidding is live and after settlement (the settled path swaps the escrow card for peak escrow and adds a settlement section). All figures come from contract views plus a full event replay in `src/stats.ts`: `BidPlaced`/`BidIncreased`/`BidDisplaced` reconstruct every bid's lifecycle, and the clearing-price curve is sampled **once per transaction** (a displacing bid emits `BidDisplaced` + `BidPlaced` in one call, so per-event sampling would draw a phantom dip to the reserve). Scheduled end is derived as `absoluteEndTime - MAX_TOTAL_EXTENSION` (the only on-chain record of the published end). "Total volume" is gross ETH committed (opening bids + top-ups, including refunded ones); escrow, sale value (`clearing x winners`) and winner change are reported separately and defined in the report footer. Logs/timestamps/tx senders/ENS/receipts cache under `cache/` keyed by address, so mid-auction re-runs only fetch new blocks (`--fresh` discards). Flags: `--gas` (receipt per bidding tx), `--no-ens`, `--no-usd`, `--svg`, `--fresh`. Config falls back to `../frontend/.env.local`, so pointing it at a Sepolia rehearsal auction is just env overrides. NOTE: `opentype.js` 2.x cannot shape Hanken Grotesk's `ccmp` table, so `src/text.ts` sums glyph advances directly instead of calling `getAdvanceWidth`.
